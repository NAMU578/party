# 파티 게임

친구들과 브라우저에서 바로 하는 온라인 파티 게임. 미니게임을 랜덤 순서로 돌아가며 하고, 점수를 합산한다.
한 라운드에서는 같은 미니게임을 두 판 연속으로 하고(`config.js`의 `flow.playsPerRound`), 두 판 점수를 합친 결과를 라운드 끝에 한 번 보여 준다.
설치 없이 링크로 접속하며, 방장 브라우저가 판정을 맡는 P2P 방식(PeerJS)이다.

## 실행 방법

JS 모듈을 쓰기 때문에 `index.html`을 더블클릭하면 동작하지 않는다. 아래 중 하나로 연다.

- VS Code의 Live Server 확장으로 `index.html` 열기
- 터미널에서 이 폴더로 이동 후 `python -m http.server 8000` 실행 → `http://localhost:8000`

혼자 테스트할 때는 탭 두 개를 열어 한쪽은 방 만들기, 다른 쪽은 방 코드로 참가하면 된다.
방장 혼자 시작해도 게임이 진행된다 (혼자일 때는 떨어질 때까지 계속됨).

## 깃허브 페이지 배포

1. 깃허브에 새 저장소를 만들고 이 폴더의 파일을 그대로 올린다 (`index.html`이 저장소 최상단에 오도록).
2. 저장소 Settings → Pages → Source를 `Deploy from a branch`, 브랜치 `main`, 폴더 `/ (root)`로 저장한다.
3. 잠시 후 `https://<아이디>.github.io/<저장소이름>/` 주소로 접속된다.
4. 방장이 방을 만들고 `초대 링크 복사`로 받은 주소를 친구에게 보내면 방 코드가 자동으로 채워진다.

## 조작

- WASD 또는 방향키: 이동 (한글 자판 상태에서도 동작)
- 스페이스바: 밀치기. 앞에 있는 사람이 밀려나며 넘어지고, 누운 채 잠시 경직된 뒤 손을 짚고 일어난다 (일어나는 동작부터 이동 가능).
  넘어진 사람은 일어날 때까지 다시 맞지 않는다. 수치는 `config.js`의 `push`에서 조절한다.
- 분류 작업에서는 걷기·밀치기 대신 스페이스바(그림 버리기)와 엔터(장치 넘기기)만 쓴다.
- 식사 예절에서는 걷기·밀치기 대신 스페이스바(포크로 콩 찍기)와 엔터(포크에 꽂힌 콩 먹기)만 쓴다.
  꾹 눌러도 한 번만 동작하고, 먼저 시작한 동작은 끝날 때까지 멈출 수 없다.

## 폴더 구조

| 경로 | 역할 |
|---|---|
| `index.html`, `css/style.css` | 페이지와 UI 스타일 |
| `js/main.js` | 시작점, 미니게임 등록 |
| `js/config.js` | 인원수, 라운드 수, 타이밍 등 모든 설정값 |
| `js/net/` | PeerJS 연결(`network.js`), 메시지 종류(`protocol.js`) |
| `js/core/` | 전체 흐름(`gameFlow.js`), 점수, 미니게임 목록·공통 틀, 난수 |
| `js/render/` | 렌더러·카메라, 방 배경, 캐릭터, 절차적 텍스처 |
| `js/player/` | 키보드 입력, 내 캐릭터 조작, 밀치기·충돌 계산(`pushRules.js`) |
| `js/ui/` | 로비 화면, 게임 중 HUD·결과표 |
| `js/minigames/symbolTiles/` | 기호 타일 미니게임 (규칙, 시간표, 타일, 벽 패널, 구덩이) |
| `js/minigames/trainDodge/` | 열차 피하기 미니게임 (규칙, 턴 시간표, 통로, 피스톤·바닥등, 셔터·LED, 열차) |
| `js/minigames/sortingLine/` | 분류 작업 미니게임 (규칙, 턴 시간표, 공장·소각로, 작업대, 벨트 위 물건 흐름, 물건 모형, 점수판, 카메라) |
| `js/minigames/dinnerManners/` | 식사 예절 미니게임 (규칙·좌석, 집주인 시간표, 창고·식탁, 집주인, 접시·포크·콩, 앉은 자세·피 표현) |
| `tests/` | 단위 테스트 (`node tests/rules.test.mjs`, `node tests/push.test.mjs`, `node tests/trainDodge.test.mjs`, `node tests/sortingLine.test.mjs`, `node tests/dinnerManners.test.mjs`) |

## 미니게임 추가 방법

1. `js/minigames/새게임/` 폴더를 만들고 `MinigameBase`를 상속한 클래스를 작성한다.
   - `mount()`: 화면 구성, `begin()`: 시작, `update(dt)`: 매 프레임
   - 방장 판정은 `isHost`일 때만 하고 `broadcastEvent()`로 알린다. 참가자는 `sendEventToHost()`로 보고한다.
   - 끝나면 방장이 `finish([[1등들], [2등들], ...])`를 호출한다. 같은 묶음은 공동 순위.
2. `{ id, title, description, computeSpawns, create }` 형태의 정의 객체를 내보낸다 (`symbolTilesGame.js`의 `symbolTilesDef` 참고).
3. `js/main.js`에 `registerMinigame(새정의)` 한 줄을 추가한다.
4. 기호 타일 방 대신 자기 맵을 쓰려면 `mount()`에서 `room.group.visible = false`, `stage.setView(시점)`을 하고 `dispose()`에서 되돌린다 (`trainDodgeGame.js` 참고).
   카메라를 매 프레임 움직이려면 `stage.aim(위치, 바라볼 점)`, 맵을 어둡게 하려면 `stage.setLightLevel(배율)`을 쓰고 끝나면 1로 되돌린다 (`sortingGame.js` 참고).

## 알아둘 점

- 연결 중계는 PeerJS 공용 서버(`0.peerjs.com`)를 쓴다. 이 서버가 멈추면 방을 만들거나 참가할 수 없다.
- 학교·회사처럼 WebRTC를 막는 네트워크에서는 연결이 안 될 수 있다.
- 방장이 나가면 게임이 끝난다. 방장은 게임 탭을 계속 띄워 두어야 한다 (다른 탭으로 오래 가 있으면 브라우저가 진행을 늦춘다).
- 탈락은 각자 자기 화면 기준으로 판정해서 방장에게 보고한다. 친구끼리 하는 용도라 조작 방지는 하지 않았다.
- 밀치기 판정은 민 사람 화면 기준이고 방장이 거리를 한 번 더 확인한다. 맞은 사람 화면에서는 통신 지연만큼 조금 늦게 밀려날 수 있다.
- 충돌은 각자 자기 캐릭터를 다른 사람에게서 밀어내는 방식이라, 지연이 크면 순간적으로 살짝 겹쳐 보일 수 있다.
  열차 피하기에서 두 사람이 같은 구역에 동시에 뛰어들면 지연 동안 둘 다 들어가 보일 수 있지만, 구역 깊이가 1인용이라 곧 한 명이 밀려난다.
- 식사 예절의 집주인은 방장이 보낸 시드로 각자 화면에서 같은 시간표대로 움직인다. 시각은 각자 시작 신호를 받은 순간부터 재므로
  통신 지연만큼 사람마다 조금 어긋나지만, 걸렸는지는 자기 화면에 보이는 신문 기준으로 판정한다.
  다른 사람이 총에 맞는 장면은 그 사람의 보고가 도착한 뒤에 보여서 조금 늦을 수 있다.
  시간 제한이 없어서, 먹고 있는 사람이 아무것도 안 하면 그 사람이 나갈 때까지 끝나지 않는다.
